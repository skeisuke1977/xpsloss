v0.1.0 の対象は M0、M1、M2-1 である。段階3（公開用の履歴と非公開リポジトリでの CI）は完了した。利用者のレビュー（2026-11-20）を受けた段階4a（数値の頑健性）、4b（近似と適用範囲の明示）、4c（検証の再現性）、4d（文書の更新）は完了した（[検証記録](VALIDATION.md)の「段階4a」–「段階4c」）。公開の前に、残りの段階4e を行う。リポジトリは、利用者が決めるまで非公開のままにする。[決定と担当範囲](ROADMAP.md)

## 段階4e　公開候補の検証

1. 先に直すこと（[ROADMAP](ROADMAP.md) §5 の 4e の行）。**済み（2026-11-20、[検証記録](VALIDATION.md)の「段階4e」）**:
   - CLI の標準出力・標準エラーの JSON を ASCII でエスケープして書く。材料名、出力先、エラー文中の入力パスの3つで試験を加える。
   - `generate.py --check` は、数値の列を許容幅で比べる（OS や CPU による末位の違いを避ける）。
   - `predict --check` に、同梱の予測ファイルと登録時の SHA-256 との照合を加える。
2. CI に `predict --check` と `generate.py --check` を加える。**済み。**
3. 修正後の候補を、利用者が非公開リポジトリに push する。同じコミットで、CI の全ジョブ（4環境と配布物）が合格することを確かめる。sdist は、追跡外のファイル（利用者のレビュー資料など）が入らないよう、クリーンなツリーから作る。
4. 別担当の最終点検で blocker がないことを確かめる。公開、タグ、外部への連絡、Zenodo 連携は利用者が担当する。参照ソフトの出力は公開しない。[検証記録](VALIDATION.md)・[帰属表示と配布範囲](../NOTICES.md)

## 公開後の候補　M2-2
